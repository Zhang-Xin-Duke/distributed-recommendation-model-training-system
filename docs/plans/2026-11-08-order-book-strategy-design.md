# Order book workload for the strategy benchmark

Use a DeepLOB-style model on FI-2010 to measure strategy behavior on a financial time-series task. The model consumes 100 consecutive snapshots with 40 book features and predicts down, unchanged or up. It combines convolution, multi-scale temporal filters and a recurrent layer. The flat-weight step exposes logits, cross-entropy and gradients for the supplied parameters. The model contains 142,435 trainable FP32 parameters. [DeepLOB paper](https://arxiv.org/abs/1808.03668) · [FI-2010 paper](https://arxiv.org/abs/1705.03233) · [Author implementation](https://github.com/zcakhaa/DeepLOB-Deep-Convolutional-Neural-Networks-for-Limit-Order-Books)

Use the authors' NoAuction DecPre files and record their checksums. Keep the official chronological train and test partitions. Carve validation from the end of the training period and exclude windows and label horizons crossing the split. Use one fixed prediction horizon and report the selected horizon and class counts. Keep evaluation on the same held-out windows for every policy. Use validation cross-entropy as the time-to-quality metric and report macro F1 and class-wise recall. Use the test split once the model and comparison criteria are fixed.

First connect the flat-weight step to the parameter service, with explicit row packing and deterministic initialization. Check one distributed synchronous update against a TensorFlow reference using the same weights and batch. Then verify repeated six-worker execution and classify the bottleneck from model device time, staging, RPC, synchronization and GPU samples. Keep a common fixed sample budget and a separate equal-quality comparison. Record the difference in optimizer updates between per-Worker and round-synchronous policies. The target loss needs calibration on the development split before comparing policies. Use the old synthetic run to diagnose communication behavior and record the new model as a separate workload.

The runnable entry point is `tests/order_book_strategy_workloads.py`. Prepare an NPZ from the author's `data.zip` with `--prepare data.zip --data fi2010.npz --train-rows 180000`. The current experiment uses the first FI-2010 label row and uses the first official test fold as development validation. Later test folds are reserved. Upload the same prepared NPZ to the same absolute path on each host. Every Worker checks the input hash before starting.

Use `--reference --iterations 1 --repeats 1 --batch-size 8` with one remote Worker first. The reference feeds the concatenated global batch into a single TensorFlow model, then compares every weight and both Adam moments after one update. Continue to the six-host run only after the reference passes.

Start GPU utilization calibration at 512 windows per Worker, then increase to 1,024 if the device has room and utilization remains low. Fix the selected batch size for all policies. Freeze the target before the paired comparison and record unsuccessful endpoints. Use the same optimization settings, data and GPU precision across policies. Each Worker records GPU utilization and memory at 200 ms intervals during the timed run, along with per-step admission, Pull, model and staging, update and completion times. The model uses dense packed weights, so these results describe dense-gradient traffic through the parameter service.
